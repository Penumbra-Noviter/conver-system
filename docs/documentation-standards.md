# Conver System 移动端 — 文档规范 (Documentation Standards)

> 与桌面库同构的文档架构规范。核心原则：**同一信息只允许存在于一个文档，其他文档引用而非复制**——凡在两处出现即漂移信号，须立即合并或改为引用。

---

## 一、文档清单与单一事实来源分配

| 文档 | 角色 | 唯一来源（什么信息只归它管） |
|------|------|------------------------------|
| `docs/mobile-design.md` | **设计唯一事实来源** | 架构 / 7 项功能映射 / 模拟器专题 / UI 设计系统 / 里程碑 / 风险。改设计先改这里 |
| `CONSENSUS.md` | 决策登记 | 已拍板决议的**登记与变更记录**（详版决策表在设计文档 §0/§4.5）；ADR 索引 |
| `TICKETS.md` | **唯一待办事实来源** | 所有未完成/已归档工单（含完成日期 + 提交哈希）。待办**绝不落** DEV_LOG / memory / 个人笔记 |
| `DEV_LOG.md` | 已做 + 避坑 | 完成记录、bug 根因、过程遥测。只记「已做」，不记待办 |
| `TECH_DEBT.md` | 技术债候选池 | 未立项候选（编号/来源/强度/状态）+ 处置记录；不自动进入 preflight |
| `PROJECT_REFERENCE.md` | 项目介绍 | 一句话、当前状态、关键决策、常碰坑点。**不复制技术细节** |
| `CLAUDE.md` | 行为规矩 | 技术栈 / 目录约定 / 跑法 / 测试规范 / 档位制 |
| `CONTEXT.md` | 领域词汇 | load-bearing 术语登记；与桌面共享术语指向桌面库 `desktop/CONTEXT.md` |
| `README.md` | 用户视角 | 安装、使用、快速开始、版本控制约定 |
| `SECURITY.md` | 安全边界 | 安全模型 / 威胁边界 / 契约声明 |
| `CODE_WIKI.md` + `scripts/doc_sync.py` | 完整档（升档后） | 技术细节单一权威源 + 机械防漂移。**模块数 ≥ 8 且文档 > 1 页时自动升档**（对齐桌面库） |

## 二、格式约定

### DEV_LOG.md
- 格式：`YYYY-MM-DD | <操作> | <描述>`，**倒序，最新在前**，滚动窗口上限 12 条。
- 只记「已做」与决策/避坑；待办一律进 TICKETS；bug 修复保留「根因 + 修复方案」。

### TICKETS.md
- 状态流转：📝 已录入 → 🔄 进行中（开始实现前认领）→ ✅/❌ 完成 → 移入「已完成归档」并记完成日期 + 提交哈希。
- 活跃表只保留未完成工单；新评审候选立即录入 TECH_DEBT.md 候选池。

## 三、测试规范（Testing Standards）

- `flutter test`（纯 Dart 单测 + 无头 widget 测试），覆盖率目标 ≥ 90%。
- 分层验证（设计 §7.1）：业务逻辑/Widget → `flutter test`（宿主无头）；编译 → `flutter build apk`；Android 运行 → 模拟器/真机；iOS → macOS/CI。
- 平台薄层（WebView 桥 / SecureStorage / 端口绑定）用真机/模拟器专项验证，不靠单测代替。

## 四、跨端（桌面 ↔ 移动）引用约定

- 工作区两个仓库：`desktop/`（main 分支）与 `mobile/`（mobile 分支），托管于同一 GitHub 仓库的两个分支。
- 从一个仓库引用另一仓库的文件：**一律写工作区路径代码段**（如 `desktop/CONSENSUS.md`、`mobile/docs/mobile-design.md`），不写相对链接——两分支各自持树，GitHub 网页端无法跨分支解析。
- 共享领域事实（角色卡 V2、存档互迁格式等）权威定义保留在桌面库，移动端引用不复制。
